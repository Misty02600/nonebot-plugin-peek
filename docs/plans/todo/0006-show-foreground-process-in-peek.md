# PLAN-0006: 在 `/peek` 回复中显示前台进程名

## 状态

待办

## 想做什么

保留 `/peek` 现有桌面截图，在成功回复的图片前增加文字消息段：
`当前应用：Code.exe`。应用信息来自同一次 `/screen` 请求返回的可选
`X-Peek-Foreground-Process` 响应头。

## 为什么值得做

只看截图不一定能快速判断当前正在使用哪个应用，尤其是在截图经过高斯模糊时。直接显示可执行文件名
能提供足够的辨识度，同时避免窗口标题泄露网页标题、文档名等额外隐私信息。

## 希望最后是什么样

- `PeekAPIClient` 解码 UTF-8 百分号编码的前台进程响应头，并通过响应类型暴露可选进程名。
- 普通模糊截图和超级用户原图都显示进程名；不新增命令参数或配置项。
- 成功回复按“`当前应用：<进程名>` 文字段、图片段”的顺序构造，通知群和通知用户继续转发同一完整回复。
- 旧 PeekAPI 没有该响应头、响应头为空或无法解码时，保持原来的纯图片回复，不显示“未知”。
- 401、403、服务错误及备用图片/文字逻辑保持不变。

## 做到什么算完成

- 客户端测试覆盖响应头存在、缺失、Unicode 百分号编码和无效值。
- 命令测试确认文字段位于图片前，且无进程名时不产生额外文字。
- 错误响应、通知转发、多主机选择、模糊半径和原图权限测试无回归。
- README 说明 `/peek` 的新增展示行为以及与旧 PeekAPI 的兼容回退。
- pytest、Ruff 和 BasedPyright 检查通过。
